## Important things I learned

In Module 3, I learned that data classification and categorization are important because they help an organization decide which security controls are needed for different types of data.  
Data can be classified by sensitivity, jurisdiction or criticality. It can also be categorized by regulatory requirements, business function, department or project.

A key point was that the **data owner** is responsible for classifying and categorizing the data because the data owner understands the value and use of the data best.

I also learned that data should be protected during its full life cycle:

- **Create**
- **Store**
- **Use**
- **Share**
- **Archive**
- **Destroy**

The data life cycle does not always happen in a strict order. Data can move between different phases depending on how it is used.

Another important point was that data protection depends on functions, locations and actors.  
Functions describe what can be done with the data, locations describe where the data is stored or processed, and actors describe who can access or use the data.

I learned that **IRM** and **DRM** are used to control access to information and protect sensitive documents or digital content.  
IRM is more focused on business documents like spreadsheets, presentations and files, while DRM is often connected to intellectual property and digital media.

Data retention was also an important topic. A data retention policy defines how long data should be kept, where it should be stored, how it should be protected and how it can be retrieved.  
This is important because companies often have legal, regulatory and business requirements.

I also learned about data audits and logging. Logs are important because they help show what happened, when it happened, where it happened and who was involved.  
A **SIEM** system can collect and analyze logs from different systems and help with alerting, dashboards, compliance reporting and forensic analysis.

For data deletion in the cloud, I learned that normal deletion is not enough because it usually only removes pointers to the data.  
In cloud environments, physical destruction and degaussing are not realistic because the customer does not control the physical hardware.  
Because of that, **crypto-shredding** is an important method. It means destroying the encryption keys so the encrypted data can no longer be read.

In Module 4, I learned more about cloud storage architecture.  
Cloud storage can use volume storage, object storage, structured data, unstructured data, information storage and content or file storage.

I learned that **IaaS** commonly uses volume storage and object storage.  
Volume storage works like a virtual hard drive attached to a virtual machine.  
Object storage stores data as objects with metadata and a unique identifier, often accessed through APIs.

I also learned that the **management plane** is a very powerful part of cloud infrastructure.  
It can create, start and stop virtual machines and assign resources like CPU, memory, storage and network connectivity. Because it has so much control, it needs strong authentication, access control, logging and monitoring.

Another important topic was encryption and key management.  
Encryption can protect data at rest, data in transit and data in use, but the keys must be protected carefully.  
If the encryption keys are lost, the data can also become unavailable.

I also learned that key management should ideally be separated from the cloud provider.  
This helps reduce the risk that the same provider has access to both the encrypted data and the encryption keys.

The course also explained alternatives to encryption, such as:

- Masking
- Obfuscation
- Anonymization
- Tokenization

These methods can help protect sensitive data, especially personally identifiable information.

In the cloud platform risk section, I learned that the cloud customer and cloud provider share responsibilities, but the customer is still legally responsible for the data they own.  
This means the customer must understand contracts, service level agreements, logging, auditing and compliance requirements.

I also learned about vendor lock-in and vendor lockout.  
Vendor lock-in happens when it becomes difficult to move away from a provider because of technical or contractual limitations.  
Vendor lockout happens when a provider is no longer available, for example because it goes out of business.

The last big topic was disaster recovery and business continuity.  
Business continuity is about keeping the business running during a disruption.  
Disaster recovery is about restoring systems and services after a disaster.

Important terms were:

- **RPO**: how much data the organization can afford to lose
- **RTO**: how long it should take to restore operations
- **WRT**: time needed to verify systems after recovery
- **MTD**: maximum time the organization can tolerate being down
