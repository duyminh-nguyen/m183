## Important things I learned

I learned that secure application development should start early in the software development life cycle.  
Security should not only be added at the end because fixing security problems after deployment is usually more expensive and harder.

The SDLC includes phases such as planning, requirements analysis, design, development, testing, integration, operation and maintenance.  
In cloud applications, secure operations are also important because applications are often updated continuously.

I also learned about software testing.  
Static Application Security Testing checks code while it is not running, while Dynamic Application Security Testing checks an application while it is running.  
Both methods are useful because they find different types of security problems.

Penetration testing was another important topic.  
A penetration test tries to simulate a real attack and includes steps like planning, reconnaissance, vulnerability analysis, exploitation and reporting.  
The report must be protected because it can contain sensitive information about weaknesses.

In cloud application architecture, I learned that multi-tenancy creates extra security risks.  
Because different customers can use the same cloud infrastructure, cloud systems need strong isolation, access control and protection against data bleed.

Another topic was auditing in the cloud.  
Auditing is harder in cloud environments because customers do not always have direct access to the provider's systems and logs.  
Frameworks and reports like the Cloud Controls Matrix and SOC reports can help customers understand and verify cloud controls.

For cloud security operations, I learned that availability and uptime are very important.  
Cloud data centers use redundancy, monitoring, maintenance and different data center tiers to keep services available.

I also learned that monitoring is not only about software.  
Hardware, network usage, temperature, humidity, airflow, HVAC systems and cable management can also affect cloud operations and availability.

Change and configuration management was another important topic.  
A baseline defines the normal and approved state of systems.  
Changes should go through a controlled process so that unauthorized or risky changes do not affect the cloud environment.

In the risk management part, I learned the difference between risk appetite and risk tolerance.  
Organizations must decide which risks they can accept and which risks need to be avoided, mitigated or transferred.

I also learned that security training and awareness are important because everyone in an organization is part of security.  
Training can be initial, recurring or refresher training, and it should be documented to show due diligence.

In the legal and compliance part, I learned about criminal law, civil law, administrative law, contracts, regulations, standards and frameworks.  
This is important in cloud computing because data and services can cross countries and jurisdictions.

I also learned that laws, regulations, standards and frameworks are not the same.  
Laws and regulations are legally required, while standards and frameworks help organizations structure their security and compliance work.
